# 云迁移预案

## 现状：Cloudflare Pages 部署

目前 dora-beads-pattern-converter 部署在 Cloudflare Pages，优点：

- 全球 CDN 加速
- 免费 HTTPS、自动部署
- 简单易用，适合开发测试

缺点：

- 国内访问速度受限
- 无法直接接入国内云服务（腾讯云、阿里云）
- 不支持 WebSocket、流媒体等
- 商业化时需要转移数据所有权

## 为什么需要国内云迁移

1. **合规性**：用户数据必须存储在国内（符合工信部规定）
2. **访问速度**：国内用户直连腾讯云/阿里云节点，延迟更低
3. **生态协作**：支付、登录、AI 等能力需要国内云接入
4. **成本控制**：大流量下国内云更便宜

## 路线对比

### 方案 A：纯 Cloudflare（当前）

```
Web: Cloudflare Pages
Database: 本地数据库（sqlite）
Storage: 本地浏览器存储
AI: 无
缺点：无法商业化
```

### 方案 B：纯腾讯云

```
Web: 腾讯云 CloudBase（前端托管）
Database: 腾讯云数据库 MongoDB / TencentDB
Storage: 腾讯云对象存储 COS
AI: 腾讯云智能图像处理
优点：完整的国内生态
缺点：全家桶，学习成本高
```

### 方案 C：纯阿里云

```
Web: 阿里云 OSS 静态托管
Database: 阿里云 MongoDB / PolarDB
Storage: 阿里云对象存储 OSS
AI: 阿里云视觉智能平台、万相设计
优点：AI 能力强、设计服务丰富
缺点：无专门的前端托管平台
```

### 方案 D：混合路线（推荐）✅

```
短期（v0.5.x ~ v0.6.0）
├─ Web: 继续 Cloudflare（开发快速）
├─ Database: 本地 mock
├─ Storage: 本地 mock
└─ AI: 本地 mock

中期（v0.6.1 ~ v0.6.2）
├─ 抽象云服务层（StorageService、DatabaseService、AiService）
├─ 搭建腾讯云 CloudBase 测试环境
├─ 迁移数据库、存储、认证到腾讯云
└─ 预留 AI 接口

长期（v0.7.0+，商业化前）
├─ Web: 迁移至腾讯云 CloudBase + 国内 CDN
├─ Database: 腾讯云 MongoDB / 云数据库
├─ Storage: 腾讯云 COS（对象存储）
├─ Auth: 腾讯云账号体系（微信、QQ 登录）
├─ AI: 
│  ├─ 去背景：腾讯云智能图像处理
│  ├─ 风格化：阿里云视觉智能 / 万相设计
│  └─ 超分：腾讯云或阿里云
└─ Payment: 微信支付、支付宝（直接接入）
```

## 关键决策

### 云数据库方案

**决定：腾讯云 MongoDB + 阿里云对象存储 COS**

原因：
- MongoDB 适合灵活的文档存储（PatternData、ProjectFiles）
- COS 性价比高，支持分片存储大文件
- 混合方案成本最低

### AI 图像处理

**决定：优先腾讯云智能图像，后期补充阿里云视觉**

原因：
- 腾讯云智能图像集成度高，接入简单
- 阿里云视觉智能功能更丰富（扩展性好）

### 用户认证

**决定：腾讯云账号 + 社交登录（微信、QQ）**

原因：
- 腾讯云原生支持微信登录
- 无需维护独立的用户密码系统
- 小程序可直接复用

## 风险与缓解

| 风险 | 影响 | 缓解措施 |
|-----|------|---------|
| 数据迁移失败 | 用户作品丢失 | 做好备份，灰度迁移 |
| 云成本超预算 | 商业化不可行 | 做成本预算压测 |
| 数据合规问题 | 无法上线 | 咨询法务，选正规云服务 |
| 性能退化 | 用户体验差 | 压测 + 本地缓存 |

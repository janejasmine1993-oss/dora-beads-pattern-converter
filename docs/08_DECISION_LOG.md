# Decision Log

## 2026-06-04（v0.3.4）

### 决策

镜像功能通过"坐标映射"而非 `ctx.scale(-1, 1)` 实现。

### 原因

`ctx.scale(-1, 1)` 会导致整个 Canvas 内容镜像，包括所有文字（品牌文案、色号、坐标、图例、水印），文字将变成反向字体无法读取。使用 `mirroredCol = width - 1 - col` 只改变格子内容的 x 坐标映射，所有文字以正常方向绘制在原位置，保持可读。

### 影响

渲染循环需要区分"视觉列"（绘制位置）和"源列"（数据来源），两次循环都要正确计算 `drawCol`。

## 2026-06-03（v0.2.5）

### 决策

部署平台使用 Cloudflare Pages，Wrangler CLI 手动部署，不添加额外配置文件。

### 原因

本项目是纯静态 SPA，无客户端路由、无环境变量、无后端。Vite 默认构建输出可直接部署。Cloudflare Pages 已通过 Wrangler 上线，稳定运行。

### 影响

每次更新需手动执行 `npm run build` + `npx wrangler pages deploy dist --project-name dora-beads-pattern-converter`。可升级为 GitHub 自动部署（步骤见 docs/11_DEPLOYMENT.md）。

## 2026-06-03（v0.2.0）

### 决策

色号匹配使用 Lab 色彩空间 + Delta-E 76 算法，而非 RGB 欧氏距离。

### 原因

RGB 欧氏距离与人眼感知色差不一致（例如蓝色通道变化在视觉上不如绿色明显），Lab 色彩空间接近人眼感知，Delta-E 是行业标准。对于拼豆色号匹配，视觉准确性比计算速度更重要。

### 影响

Lab 转换需要额外计算（sRGB → linear → XYZ → Lab），但对 200×200 以内的图纸性能可接受。后续如需更高精度可升级为 CMC(1:1) 或 Delta-E 2000。

## 2026-06-03（v0.2.0）

### 决策

生成流程设计为"手动触发"（点击按钮），而不是上传或修改尺寸后自动触发。

### 原因

自动触发会导致用户修改宽高时每次输入都触发一次完整计算，用户体验较差。手动触发让用户可以确认所有参数后再执行。

### 影响

切换品牌例外：品牌切换只重新匹配（不重新像素化），速度快，所以设计为自动触发。

---

## 2026-06-03（v0.1.0）

### 决策

第一阶段只做 MVP，不做登录、支付、会员、小程序、后台管理、云端保存和复杂 AI 能力。

### 原因

避免项目过大，先保证拼豆图纸转换器的核心流程稳定，防止项目跑偏和混乱。

### 影响

高级功能只做占位和接口预留，不影响 MVP 主流程。

---

## 2026-06-03（v0.1.0）

### 决策

Tailwind CSS 使用 v4 + `@tailwindcss/vite` 插件方式集成，不使用 v3 的 PostCSS 配置。

### 原因

项目使用 Vite，v4 的 Vite 插件方式更简洁，无需额外 PostCSS 配置。

### 影响

CSS 入口使用 `@import "tailwindcss"` 代替 v3 的 `@tailwind base/components/utilities`。

---

## 2026-06-03（v0.1.0）

### 决策

色卡数据第一阶段使用示例数据，不凭空编造真实品牌色号。

### 原因

真实品牌色卡数据需要后续从 GitHub 开源项目中核实，避免引入不准确的数据影响后续算法调试。

### 影响

后续接入真实色卡时需要统一整理格式并确认开源协议。
